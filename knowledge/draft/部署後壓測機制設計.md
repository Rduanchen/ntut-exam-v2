# 部署後壓測機制設計 (Post-Deployment Stress Test)

## 緣起與問題
每次部署至新考場時（通常經由筆電轉接或無線網卡連線），硬體效能與網路環境皆不一致。若無部署後測試，極容易在學生考試當下才發現系統崩潰或網路瓶頸。同時，我們需要符合行業標準的精確數據（如 P99 延遲、RPS、錯誤率）來評估主機負載能力。

## 設計提案
引入「部署後壓測機制」，結合後端效能測試與前端 Admin UI，讓管理員能一鍵執行並檢視報告。

### 具體機制
1. **後端整合 `autocannon`**：
   - 在後端實作專屬壓測 API（如 `POST /api/admin/system-test`）。
   - API 內部透過 Node.js 呼叫 `autocannon` 模組，對系統自身的評測端點發起模擬高併發請求（可配置併發數與持續時間）。
   - 收集並回傳標準效能數據（Percentiles、RPS、Timeout 統計等）。
2. **前端 Test Tab 實作**：
   - 在 Admin UI 新增 `Test Tab`（測試頁籤）。
   - 提供「啟動壓測」介面，讓管理員設定參數。
   - 接收後端回傳的 JSON 報告後，利用圖表視覺化呈現延遲分布與穩定度。
