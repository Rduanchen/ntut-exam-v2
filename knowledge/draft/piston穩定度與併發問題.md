# Piston 穩定度與併發問題排查

## 緣起與問題
目前後端 `judger.service.ts` 使用 `p-limit(5)` 控制最多 5 個併發請求呼叫 Piston 進行程式碼評測。然而，系統隨機出現 Compile Error (CE)。
這可能是因為：
- Piston 容器後端在高併發下資源衝突或不足。
- 套件相容性問題。
- 外部編譯器呼叫機制的潛在缺陷。

## 待辦排查方向
1. 深入檢查 Piston Server 在處理多份程式碼時的實際負載與隔離機制。
2. 驗證並優化目前的並行控制。
3. 評估是否有其他更穩定的評測核心可取代 Piston，或改善現有的呼叫模式。
4. 驗證助教端觸發重啟或評測後，學生頁面的輸出能否正確覆蓋。

## 狀態
In-flight Rationale (進行中)。屬於待解決的核心系統不穩定問題。
