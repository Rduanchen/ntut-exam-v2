# Feature Specification: 管理介面繁體中文用語統一

**Feature Branch**: `尚未建立（目前工作分支：feat/009-download-sqlite-backup）`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "掃描這個專案的前端檔案，將大部分頁面的中英文夾雜統一成繁體中文；專業術語及必要之處維持英文。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 以一致的繁體中文瀏覽管理介面 (Priority: P1)

管理員或助教在不同管理頁面切換時，可直接讀懂導覽、標題、欄位、按鈕與提示，不必在中英文之間反覆切換。

**Why this priority**: 跨頁面用語一致是這次調整的主要價值，也直接影響考場操作速度。

**Independent Test**: 逐一開啟九個主要導覽頁面及其分頁、對話框，比對可見文字與用語表；即使其他故事尚未完成，主要操作仍可用繁體中文理解。

**Acceptance Scenarios**:

1. **Given** 管理員進入管理介面，**When** 瀏覽側邊導覽與頁面標題，**Then** 一般介面文字均為繁體中文，同一概念在各頁使用相同譯名。
2. **Given** 管理員在考試管理、設定、評測、成績、學生、防作弊、紀錄、連線及設備頁面操作，**When** 查看欄位、按鈕、篩選條件、說明或空白狀態，**Then** 可理解的日常文字均為繁體中文。
3. **Given** 某欄位使用 IP、UUID、JSON、CSV、Piston 等辨識所需術語，**When** 顯示欄位名稱或說明，**Then** 保留必要英文縮寫，周邊操作語句仍為繁體中文。

---

### User Story 2 - 以中文理解狀態與異常 (Priority: P2)

管理員或助教在載入、等待、成功、失敗、無資料及連線異常時，能立即看懂畫面狀態與可採取的操作。

**Why this priority**: 狀態與錯誤訊息會影響考試現場判斷，尤其不能混淆學生作答失敗與系統故障。

**Independent Test**: 在主要頁面分別觸發載入、空資料、成功與失敗情境，確認畫面文案、狀態名稱及必要診斷資訊。

**Acceptance Scenarios**:

1. **Given** 頁面正在載入或沒有資料，**When** 管理員查看提示，**Then** 提示以繁體中文說明目前狀態。
2. **Given** 評測或環境檢查回報失敗，**When** 管理員查看結果，**Then** 中文說明保留原本的失敗歸因與必要的技術代碼，不把系統故障誤寫成學生答題錯誤。
3. **Given** 系統回傳無法直接辨識的原始診斷內容，**When** 畫面顯示錯誤，**Then** 中文提示說明操作未完成，原始內容仍可供診斷且不被錯譯。

---

### User Story 3 - 安全完成高風險操作 (Priority: P3)

管理員在解除設備綁定、註銷設備、重設考試資料等操作前，能從繁體中文警告理解後果，且原有確認門檻持續有效。

**Why this priority**: 警告翻譯錯誤或改壞確認規則，可能使正在考試的學生被意外登出或資料被重設。

**Independent Test**: 走查每個高風險確認對話框的警告、確認與取消流程；確認文案、操作結果與門檻符合原有行為。

**Acceptance Scenarios**:

1. **Given** 線上學生的設備即將解除綁定，**When** 管理員開啟確認對話框，**Then** 繁體中文警告清楚指出會立即登出學生及影響考試進度。
2. **Given** 操作要求輸入固定確認字串 `CONFIRM`，**When** 管理員只閱讀或輸入其他內容，**Then** 確認操作仍不可執行；畫面以中文說明必須輸入的字串。
3. **Given** 管理員取消高風險操作，**When** 關閉對話框，**Then** 不會執行原操作。

### Edge Cases

- 後端或使用者產生的原始文字含英文、程式碼、檔名、路徑或識別碼時，畫面不得擅自改寫其內容；必要時另附繁體中文標籤或解釋。
- 同一英文值同時用於顯示與資料交換時，只翻譯顯示名稱，不改變既有值與操作結果。
- 評測縮寫（例如 AC、WA、TLE、MLE、CE、SE）若作為結果代碼，保留原碼並以中文說明含義；未知代碼保留原文，避免推測。
- 長篇中文警告、窄螢幕及表格欄位須完整可讀，不得因換行或截斷隱藏關鍵後果或操作條件。
- 使用者自行輸入的考卷標題、題目、測資、廣播內容及提交程式碼不屬於介面翻譯內容。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理介面 MUST 以繁體中文顯示九個主要導覽區域的導覽名稱、頁面標題及一般操作文案：考試管理、考試設定、評測、成績、學生、防作弊、紀錄、連線與設備。
- **FR-002**: 介面 MUST 統一各頁的欄位標籤、按鈕、分頁、篩選選項、表格標頭、佔位提示、說明文字、對話框、空白狀態及載入訊息用語。
- **FR-003**: 介面 MUST 將自身產生的成功、失敗、驗證與操作警告訊息改為繁體中文；對不可辨識的外部錯誤，MUST 提供中文情境說明並保留原始診斷內容。
- **FR-004**: 同一概念 MUST 使用一致譯名，至少包含考試階段、設備與連線狀態、評測狀態、警告處理狀態及常見操作；同頁不得同時出現互相矛盾的稱呼。
- **FR-005**: 專業縮寫、產品或語言名稱、資料格式、單位與需要精確辨認的代碼 MAY 保留英文；保留時，周邊可翻譯的語句 MUST 為繁體中文，且首次可能造成誤解的代碼 MUST 有中文說明。
- **FR-006**: 此次文字調整 MUST 保持既有操作語義、權限、資料內容、篩選結果及高風險操作確認條件；固定確認字串 `CONFIRM` MUST 保持原樣。
- **FR-007**: 評測及環境檢查的中文文案 MUST 清楚區分學生作答問題與系統故障，且不得將未確定歸因的失敗表述為學生錯誤。
- **FR-008**: 介面的瀏覽器頁面名稱及主要內容語言 MUST 與繁體中文管理介面一致。
- **FR-009**: 管理介面 MUST 保留使用者輸入或外部提供之原始資料，包括考卷內容、學生資料、程式碼、日誌原文及可辨識技術識別碼。

### Non-Functional Requirements (Constitution Mandated)

- **NFR-SEC**: 文字調整不得降低考試安全性或使高風險警告不完整、不明確。
- **NFR-CONC**: 文字調整不得改變考試期間大量使用者同時操作時的既有狀態呈現與可操作性。
- **NFR-TYPE**: 顯示名稱與其對應資料值須保持明確、一致的關係，避免因翻譯造成錯誤操作。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 九個主要導覽區域及其可操作子畫面中，100% 的一般介面文案符合繁體中文用語表；必要英文例外有可辨識的理由。
- **SC-002**: 逐頁抽查的導覽、標題、欄位、按鈕、狀態及錯誤提示中，同一概念的譯名一致率達 100%。
- **SC-003**: 在至少九個主要頁面各走查載入、空資料或錯誤等適用狀態時，100% 的介面自產提示可由繁體中文讀者直接理解。
- **SC-004**: 高風險操作走查中，100% 的警告保留原有後果說明，確認門檻與取消結果均與調整前一致。
- **SC-005**: 由管理員與助教各完成一次跨頁面任務走查，兩人均能在不查英文對照表的情況下完成指定操作並正確解釋警告與狀態。

## Assumptions

- 本次範圍是此專案的管理端前端；學生桌面端、後端回應原文、對外報表內容與使用者自行輸入資料不納入翻譯。
- 採台灣常用繁體中文用語；IP、UUID、JSON、CSV、Piston、程式語言名稱、評測代碼及計量單位依辨識需要保留英文。
- 固定確認字串 `CONFIRM` 是現有安全操作條件，屬必要英文；僅調整其周邊說明。
- 現有九個導覽區域與其頁面、對話框及狀態為完整的介面盤點範圍；正式調整前仍需逐一列出使用者可見文案並建立一致譯名。

## Dependencies

- 需取得主要頁面在正常、空白、載入、錯誤及高風險操作時的實際文案，以核對遺漏與用語一致性。
- 需掌握既有評測結果、考試階段及設備狀態的含義，才能安全翻譯顯示名稱。

## Out of Scope

- 新增語言切換、多語系管理或翻譯使用者內容。
- 變更評測規則、考試流程、資料交換值、權限或後端錯誤分類。
