# Feature Specification: 下載 SQLite 資料庫備份

**Feature Branch**: `[009-download-sqlite-backup]`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "我需要增加一個功能是備份的功能，我需要再admin的街口上面做一個 api ，當有人call 這個 api 的時候會自動地回傳 sqlite 的 db"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理員下載目前資料庫的備份 (Priority: P1)

有權限的管理員呼叫管理端備份 API 後，直接取得一份可儲存、可作為還原來源的 SQLite 資料庫檔案，不必登入主機或先執行其他步驟。

**Why this priority**: 讓管理員能立即保存目前的考試資料，是此功能的主要目的。

**Independent Test**: 在已有考試資料的環境呼叫備份 API，將回傳內容存檔，確認檔案可開啟並含呼叫前已儲存的資料。

**Acceptance Scenarios**:

1. **Given** 管理員已通過既有管理端驗證且資料庫含有已儲存資料, **When** 呼叫備份 API, **Then** 回應提供可下載的 SQLite 資料庫檔案，並附可辨識的備份檔名。
2. **Given** 管理員已下載備份, **When** 以該檔案作為還原來源檢查, **Then** 檔案可正常開啟，且包含備份快照中已提交的資料及資料結構。
3. **Given** 考試正在進行, **When** 管理員呼叫備份 API, **Then** 備份完成時考試仍可正常進行，正式資料不因備份被修改或清除。

---

### User Story 2 - 保護備份中的考試資料 (Priority: P1)

資料庫備份可能含考卷、答案、學生識別資料與成績。只有通過管理端驗證的請求能取得檔案。

**Why this priority**: 未授權下載完整資料庫會直接破壞考試保密與公平性。

**Independent Test**: 分別以沒有憑證、無效憑證與有效管理員憑證呼叫 API，確認僅最後一種情況能取得檔案。

**Acceptance Scenarios**:

1. **Given** 請求沒有有效管理端憑證, **When** 呼叫備份 API, **Then** 請求被拒絕，回應不含資料庫內容。
2. **Given** 管理員憑證有效, **When** 呼叫備份 API, **Then** 系統沿用既有管理端授權規則，不另開匿名下載入口。

---

### User Story 3 - 備份失敗時收到明確結果 (Priority: P2)

如果備份無法產生，管理員會收到失敗結果，而不是看似成功、實際無法還原的檔案，並可在問題排除後重試。

**Why this priority**: 錯誤檔案若被當作成功備份，會在需要還原時才暴露問題。

**Independent Test**: 模擬資料庫無法讀取或備份產生失敗，確認呼叫者取得失敗結果，且未取得標示為成功的檔案。

**Acceptance Scenarios**:

1. **Given** 資料庫無法讀取或備份無法完成, **When** 管理員呼叫備份 API, **Then** 系統回報失敗且不將未完成檔案標示為有效備份。
2. **Given** 一次備份失敗, **When** 管理員在故障排除後重試, **Then** 可重新取得有效備份，前次失敗不改變正式資料。

### Edge Cases

- 備份期間仍有學生提交或助教評分：下載檔須代表單一一致時點，不得損毀或含互相矛盾的資料。
- 資料庫尚未建立、無法存取或內容異常：回報失敗，不提供空白檔案充作成功備份。
- 多位管理員同時下載：每位管理員取得各自有效的備份，不覆寫彼此結果或破壞考試操作。
- 用戶端中途斷線：該次傳送停止並釋放占用資源，正式資料維持可用。
- 部署未設定管理端憑證或仍使用已知預設值：備份下載拒絕提供完整資料庫，管理員收到可處理的暫時性失敗結果。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供一個管理端 API，單次呼叫即可取得目前使用中的 SQLite 資料庫備份。
- **FR-002**: 該 API MUST 使用既有管理端驗證；缺少、使用無效憑證，或部署仍使用已知預設管理憑證時 MUST 拒絕下載，且不得回傳任何備份資料。
- **FR-003**: 成功回應 MUST 提供可直接儲存的資料庫檔案，並以可辨識的檔名標示其為備份。
- **FR-004**: 備份 MUST 是可正常開啟、可用於還原的完整資料庫，包含備份快照時已提交的資料及資料結構。
- **FR-005**: 即使備份期間有資料寫入，備份 MUST 保持單一時點的一致性，且 MUST 不修改、清除或中斷正式考試資料。
- **FR-006**: 資料庫不存在、無法讀取或備份失敗時，系統 MUST 回報明確失敗，不得把不完整內容宣稱為成功備份。
- **FR-007**: 系統 MUST 允許重試備份；失敗或中途取消的請求 MUST 不影響之後的備份及正式考試操作。
- **FR-008**: 系統 MUST 對同時發生的備份請求保持結果隔離；任一請求不得取得另一請求的不完整產物。

### Non-Functional Requirements (Constitution Mandated)

- **NFR-SEC**: 備份 MUST 遵守管理端權限與資料保密要求，不得產生可公開存取的副本。
- **NFR-CONC**: 備份作業 MUST 在學生提交與助教操作持續進行時保持服務可用。
- **NFR-TYPE**: 管理端回應與錯誤處理所涉及的資料邊界 MUST 維持嚴格型別檢查。

### Key Entities *(include if feature involves data)*

- **目前資料庫**: 系統正在使用的考試資料集合，包含資料結構與已提交內容。
- **備份檔案**: 一次請求取得的資料庫一致性快照，具可辨識檔名，可由管理員下載保存並用於還原。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 資料庫正常可用的驗收案例中，100% 的授權下載都能取得可開啟、可查到備份時已提交資料的檔案。
- **SC-002**: 未提供有效管理端憑證的驗收案例中，100% 的請求都無法取得備份內容。
- **SC-003**: 備份期間同時產生學生提交與助教評分的驗收案例中，100% 的已完成備份通過完整性檢查，且正式資料沒有遺失或被改寫。
- **SC-004**: 對 100 MB 以下的資料庫，在一般考場部署環境中，95% 的授權請求於 30 秒內開始下載。
- **SC-005**: 資料庫無法存取或備份失敗的驗收案例中，100% 的請求清楚回報失敗，不提供標示為成功的檔案。

## Assumptions

- 此功能提供按需下載，不包含排程、自動保存歷史版本或還原操作。
- 「admin 的接口」指既有管理端 API；第一版不新增管理頁面按鈕。
- 備份涵蓋目前運作中使用的單一 SQLite 資料庫，不包含資料庫外的設定檔、上傳檔或紀錄檔。
- 管理員自行保存下載檔案；系統不建立可供其他人取得的長期備份副本。
- 既有管理端憑證與驗證流程是此功能的前置依賴；管理憑證必須明確設定且避開專案已知預設值。
