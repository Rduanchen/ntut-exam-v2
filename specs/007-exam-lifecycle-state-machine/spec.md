# Feature Specification: Exam Lifecycle State Machine and Paper Encryption

**Feature Branch**: `feat/007-exam-lifecycle-state-machine`

**Created**: 2026-09-04

**Status**: Draft

**Input**: User description: "將後端的全域考試階段由四個重整為五個語意獨立的階段，階段單向不可逆、唯一退回通道是全域 reset；每階段明確定義後端與桌面版各自允許的操作；學生端狀態為推導值；單一學生的異常以『重來』處理而非階段退回；考卷採兩層加密，內容金鑰扣留至開考才釋出，並提供不依賴後端的離線取得路徑。"

> **相關文件**：`design.md`（本目錄）記載完整的技術設計 —— 階段矩陣、加密結構、schema 與 API 變更、與現況的差異清單。`../../EXAM-LIFECYCLE.md` 以時序圖與流程圖說明兩端的互動。本檔專注於需求本身。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 依序推進的入場流程 (Priority: P1)

管理員在考試當天依序推進考試階段。每個階段只開放該階段應該發生的事：機器先在無人的教室完成註冊與環境檢查，學生入場後才開放登入，開考後才能作答。管理員無法跳過階段，也無法把考試退回上一個階段。

**Why this priority**: 這是整個功能的骨架。沒有語意獨立的階段，「什麼時候允許什麼」就無處可掛，其他所有需求都無法表達。

**Independent Test**: 在一台乾淨的部署上依序推進五個階段，確認每個階段只允許該階段的操作、其餘一律被拒，且無法跳階或回退。

**Acceptance Scenarios**:

1. **Given** 系統尚未初始化, **When** 學生機器嘗試註冊或登入, **Then** 兩者皆被拒絕，機器停留在等待畫面。
2. **Given** 考試已初始化且開放註冊, **When** 一台考試機器啟動, **Then** 它可自助完成註冊並執行環境檢查，但無法登入。
3. **Given** 註冊已關閉、開放登入, **When** 一台**未曾註冊**的機器嘗試註冊, **Then** 註冊被拒絕並產生一筆待助教審核的請求。
4. **Given** 註冊已關閉、開放登入, **When** 一位學生在已註冊的機器上登入, **Then** 登入成功，且該生在監考端顯示為已就緒。
5. **Given** 考試進行中, **When** 管理員嘗試將考試退回「開放登入」階段, **Then** 該操作被拒絕，考試階段不變。
6. **Given** 系統處於任一階段, **When** 管理員嘗試跳過中間階段直接推進, **Then** 該操作被拒絕。

### User Story 2 - 考卷在開考前不可讀 (Priority: P1)

考卷與所有測資在開考前就已送到每台考試機器上，但在開考之前，任何在該機器前的人都無法讀取其內容。開考時才釋出解讀能力。

**Why this priority**: 這是本功能的首要安全目標。目前考卷在學生登入成功的當下即以可讀形式進入機器，而登入發生在開考之前。

**Independent Test**: 在開考前檢視一台已完成登入的機器所持有的考卷資料，確認題目敘述與測資皆不可讀；推進到開考後再檢視，確認可讀。

**Acceptance Scenarios**:

1. **Given** 機器已完成註冊, **When** 系統尚未開考, **Then** 機器可取得考卷的公開部分（用於環境檢查與入場）與不可讀的機密部分。
2. **Given** 機器持有不可讀的考卷機密部分, **When** 系統尚未開考, **Then** 系統拒絕提供任何可解讀該部分的資訊。
3. **Given** 考試已開考, **When** 機器向系統索取解讀能力, **Then** 系統提供之，且機器能還原出完整考卷。
4. **Given** 考卷的公開部分, **When** 檢視其內容, **Then** 其中不含任何題目敘述、配分、測資或解法限制。
5. **Given** 考試已結束, **When** 一台機器索取解讀能力, **Then** 該請求被拒絕。

---

### User Story 3 - 機器重啟後能回到考試 (Priority: P1)

一位學生的機器在考試中當機重啟。學生重新啟動應試程式，經助教確認後回到考試，先前已提交的作答內容自動復原。

**Why this priority**: 目前這條路徑是死路 —— 重啟必然被判為二次綁定而遭拒，且離線退路不可達，該生無法以任何方式繼續考試。這是考試現場最可能發生也最嚴重的失效。

**Independent Test**: 在考試進行中重啟一台學生機器，走完重新入場流程，確認該生回到考試畫面且已提交的作答完整復原。

**Acceptance Scenarios**:

1. **Given** 考試進行中, **When** 一台已登入的機器重新啟動, **Then** 它會自動重新申請入場，並產生一筆待助教審核的請求。
2. **Given** 助教核准該請求, **When** 學生重新登入, **Then** 系統回送其先前已提交的作答，學生直接回到考試畫面。
3. **Given** 一位學生完成重來, **When** 檢視其成績與已提交的作答, **Then** 兩者與重來之前完全相同。
4. **Given** 一位學生完成重來, **When** 觀察其入場流程, **Then** 該流程與一般學生的入場流程完全相同，包含環境檢查，沒有任何簡化或特例。
5. **Given** 一位學生尚未提交的本機作答, **When** 該機器重啟, **Then** 該部分內容遺失（已接受的限制），且系統明確告知學生。

### User Story 4 - 後端不可用時考試仍能開始與進行 (Priority: P2)

開考當下後端服務中斷。監考現場宣讀開考口令，全班照常開考。考試期間後端持續不可用，已開考的機器完全不受影響。

**Why this priority**: 開考是全場唯一無法容忍延誤的時刻。若該時刻依賴後端可用，一次跳機就會使整場考試無法開始。

**Independent Test**: 中斷後端後，僅以口令讓一台機器開考，並完整作答、評測到底。

**Acceptance Scenarios**:

1. **Given** 機器已持有不可讀的考卷且後端不可用, **When** 監考宣讀開考口令且學生輸入正確, **Then** 該機器成功開考，考卷完整可讀。
2. **Given** 學生輸入錯誤的開考口令, **When** 嘗試開考, **Then** 開考失敗且考卷仍不可讀。
3. **Given** 考試進行中後端中斷, **When** 學生繼續作答與執行評測, **Then** 兩者完全不受影響。
4. **Given** 後端中斷期間學生完成了作答與評測, **When** 後端恢復, **Then** 該期間產生的結果自動補送，不需學生重複操作。
5. **Given** 後端在考試中持續不可用, **When** 到達預定結束時間, **Then** 由監考以人工方式宣布並逐台收卷（已接受的降級程序）。

---

### User Story 5 - 全域 reset 讓系統乾淨回到起點 (Priority: P2)

管理員在考試結束後（或考前重新佈署時）執行全域 reset。所有考試資料清空，所有學生機器一併回到最初的等待狀態，不殘留任何舊考試的身分或考卷。

**Why this priority**: reset 是唯一的退回通道。目前學生機器在 reset 後幾乎不清除任何狀態，導致機器持有已失效的身分而無法重新入場 —— 使 reset 在實務上不可用。

**Independent Test**: 在考試進行中執行 reset，確認所有機器回到等待畫面且不殘留任何舊資料，接著重新初始化並讓同一批機器完成註冊。

**Acceptance Scenarios**:

1. **Given** 系統處於任一階段, **When** 管理員執行全域 reset, **Then** 考試階段回到最初狀態，所有考試資料被清空。
2. **Given** 學生機器正在考試中, **When** 系統執行全域 reset, **Then** 該機器清除身分、考卷與作答暫存，回到等待畫面。
3. **Given** reset 已完成, **When** 同一台機器在重新初始化後嘗試註冊, **Then** 註冊成功，不受任何殘留狀態阻礙。
4. **Given** reset 已完成, **When** 檢視系統, **Then** 舊考試的考卷與其解讀資訊已不存在。

---

### User Story 6 - 助教能判斷並處理入場例外 (Priority: P3)

註冊關閉後，助教在監考端逐一處理入場申請。畫面提供足夠資訊讓助教區分「同一台機器重新入場」、「全新機器」與「已註冊但未綁人的機器」，並在換機時一次完成綁定調整。

**Why this priority**: 助教核准是註冊關閉後唯一的入場閘門，也是整個安全模型的核心。判斷資訊不足會讓助教只能盲目核准，等同閘門不存在。

**Independent Test**: 製造三種入場情境，確認監考端能分別辨識，且換機情境只需一次核准即可完成。

**Acceptance Scenarios**:

1. **Given** 三種不同來源的入場申請, **When** 助教檢視待審清單, **Then** 每一筆都標示其類型，並附上原綁定學號、該學號是否在他機上線、上次斷線時間、來源位置是否與名單相符。
2. **Given** 一位學生換到另一台機器, **When** 助教核准並指定該機器對應的學號, **Then** 舊機器與該學號的綁定、以及該學號與其原機器的綁定，皆在同一次操作中解除。
3. **Given** 助教拒絕一筆入場申請, **When** 檢視系統狀態, **Then** 沒有任何裝置或學生的狀態因該筆被拒申請而改變。
4. **Given** 有人以他人的機器識別送出入場申請, **When** 該申請被拒絕, **Then** 被冒用者正在進行中的考試與其顯示狀態完全不受影響。

---

### Edge Cases

- **開考前後端中斷、機器又重啟**：機器同時失去考卷與解讀能力，兩者都只能向後端重新取得。此情況無法自動恢復，需由監考手動佈署考卷檔案。
- **機器從未連上後端**：整場維持離線，由監考手動佈署考卷檔案並以口令開考；不會因為後端稍後恢復而自動切換為線上。
- **考試中網路短暫中斷**：不視為離線，機器自動重連並補送期間累積的結果；模式不改變。
- **考試結束瞬間仍在上傳**：結束後保留一段收卷緩衝，緩衝期內仍接受提交，緩衝結束後一律拒絕。
- **考試進行中更新考卷**：機器重新取得考卷內容，沿用手上既有的解讀能力，不需重新開考。
- **全班同時重啟**（停電、網路設備重啟）：所有機器同時進入待審，助教佇列壅塞。本次不處理，記錄為已知限制。
- **開考口令外洩**：持有者可在開考前解讀考卷。已接受的風險，由作業程序（現場宣讀、不寫入電子檔）緩解。

## Requirements *(mandatory)*

### Functional Requirements

**階段與轉移**

- **FR-001**: 系統 MUST 維護單一的全域考試階段，並將其變更即時同步至所有學生機器。
- **FR-002**: 系統 MUST 提供五個語意互不重疊的階段：未初始化、已初始化（開放註冊）、設定完成（開放登入）、考試中、已結束。
- **FR-003**: 系統 MUST 只允許階段向前推進一步；跳階、回退與原地轉移 MUST 一律拒絕。
- **FR-004**: 階段轉移的限制 MUST 由系統核心強制，不得僅依賴操作介面的限制。
- **FR-005**: 系統 MUST 為每個階段定義裝置註冊、學生登入、考卷下發、解讀能力下發、提交作答與分數各自的允許與否，並在每一個對應的操作上實際檢查。
- **FR-006**: 系統 MUST 在進入「設定完成」階段時關閉裝置自助註冊（而非等到考試開始）。

**學生端狀態**

- **FR-007**: 學生機器 MUST NOT 維護獨立的考試階段；其畫面與可用能力 MUST 由全域階段與本機的註冊、綁定狀態推導而得。
- **FR-008**: 學生機器 MUST NOT 在「設定完成」之後允許使用者變更連線設定或自行載入考卷。

**入場與退回**

- **FR-009**: 系統 MUST 在自助註冊關閉後，將每一筆新的入場申請轉為待助教審核，並拒絕該次申請。
- **FR-010**: 被拒絕的入場申請 MUST NOT 改變任何裝置或學生的既有狀態。
- **FR-011**: 系統 MUST 讓助教區分「已綁定學生的機器重新入場」、「全新機器」、「已註冊但未綁定學生的機器」三種情境，並提供足以判斷的佐證資訊。
- **FR-012**: 助教核准換機時 MUST 能在單次操作中完成新舊兩邊的綁定調整。
- **FR-013**: 系統 MUST 提供「重來」路徑：清除單一裝置的身分與本機考卷後，重走與一般入場**完全相同**的流程，包含環境檢查。
- **FR-014**: 重來 MUST 保留該學生在系統中的作答與分數。
- **FR-015**: 學生機器重新啟動時 MUST 自動走上述重來路徑，不需額外操作。
- **FR-016**: 系統 MUST 提供全域 reset 作為唯一的階段退回通道，且其與一般階段轉移 MUST 可被學生機器區分。
- **FR-017**: 學生機器收到全域 reset 時 MUST 清除身分、考卷、解讀能力、環境檢查結果、評測結果、作答暫存與同步進度，並回到最初的等待畫面。

**考卷保護**

- **FR-018**: 考卷 MUST 切分為「公開部分」與「機密部分」。公開部分 MUST 僅包含環境檢查與入場流程所需的資訊。
- **FR-019**: 公開部分 MUST NOT 包含題目敘述、配分、任何測資或解法限制。
- **FR-020**: 機密部分 MUST 以獨立於裝置身分的方式保護，使持有該機器者在開考前無法讀取。
- **FR-021**: 系統 MUST 在「已初始化」階段即可將公開部分與受保護的機密部分下發給已註冊的機器。
- **FR-022**: 系統 MUST 扣留機密部分的解讀能力至「考試中」階段才釋出。
- **FR-023**: 解讀能力 MUST NOT 以任何不驗證接收者身分的方式散播。
- **FR-024**: 系統 MUST 提供第二條不依賴後端可用的解讀能力取得路徑，由監考現場提供的口令導出。
- **FR-025**: 兩條取得路徑 MUST 導出相同的解讀能力，且重複取得無副作用。
- **FR-026**: 監考口令 MUST NOT 以可直接讀取的形式出現在下發給學生機器的任何資料中。
- **FR-027**: 還原後的完整考卷 MUST 與現行的考卷結構等價，使評測、畫面與規則檢查不需因本功能而改變。

**離線與斷線**

- **FR-028**: 機器的線上/離線模式 MUST 由「是否曾成功完成裝置註冊」決定，而非由考卷的取得來源決定。
- **FR-029**: 網路中斷 MUST NOT 改變機器的模式；機器 MUST 自動持續嘗試重連。
- **FR-030**: 中斷期間產生的作答、評測結果與行為紀錄 MUST 在連線恢復後自動補送，不需學生重複操作。
- **FR-031**: 從未成功註冊的機器 MUST 維持離線至考試結束，不因後端稍後恢復而自動切換。
- **FR-032**: 供離線佈署的考卷檔案 MUST 採用與線上下發相同的保護形式，使該檔案外流不致洩漏測資。

**收卷**

- **FR-033**: 系統 MUST 在考試結束後保留一段收卷緩衝期，期間仍接受提交；緩衝期結束後 MUST 拒絕提交。
- **FR-034**: 收卷緩衝期的長度 MUST 由單一設定來源決定，並由系統實際執行，不得僅由操作介面限制。

**現場驗收後補正（Bugfix Round 1，2026-09-10）**

> 以下需求來自 007 首次完整實作後的現場走查。每一條都對應一個實際重現的失效，而不是新增的能力 —— 它們補的是既有需求在實作中沒有被真正滿足的地方。詳見 `bugfixes.md`。

- **FR-035**: 錯誤碼與人類可讀訊息 MUST 是兩個獨立欄位，且兩端 MUST 以錯誤碼（而非訊息文字）判斷後續行為。任何以訊息字串充當錯誤碼的介面 MUST 視為契約違反。
  *（BUG-04／BUG-06 的根因：`ALREADY_LOGGED_IN`、`BINDING_LOCKED`、`REGISTRATION_FAILED` 三個碼被放進訊息欄位，桌面版因此把「綁定層級的拒絕」誤判為「裝置未註冊」。）*
- **FR-036**: 登入失敗 MUST NOT 清除本機的裝置註冊。裝置註冊與學生登入是兩層獨立的狀態，任一次登入被拒 MUST NOT 使機器退回待審佇列。
  *（否則一次綁定衝突會讓機器每 5 秒重送一筆入場申請，助教佇列被同一台機器灌爆。）*
- **FR-037**: 解除綁定 MUST NOT 破壞學生的名單座位資訊。解除綁定後該學生的來源位置限制 MUST 回到設定檔宣告的值，而非變成「不限」。助教核准換機時 MUST 同時發給該次入場所需的位置例外，使換機可行而不需犧牲其他人的位置限制。
- **FR-038**: 學生機器的畫面 MUST 在**每一次**全域階段變更時重新推導，且該推導 MUST 只有一個註冊點。任何頁面 MUST NOT 自行解讀階段變更事件來決定是否留在原地。
  *（BUG-01：考試頁只處理 `FINISHED`／`IN_PROGRESS` 兩個值，reset 後整台機器停在考試畫面。）*
- **FR-039**: 機器啟動時，若預先佈署的設定已指定後端位址，MUST NOT 出現任何要求使用者輸入連線設定的畫面；機器 MUST 直接進入由全域階段推導出的畫面。
  *（BUG-02：連線狀態事件在視窗建立前就送出而遺失，機器永遠停在設定頁。）*
- **FR-040**: 離線機器（從未成功註冊、以檔案取得考卷）的畫面推導 MUST 導向可用的路徑，且 MUST 能到達以監考口令開考的入口。離線機器 MUST NOT 被導向任何需要後端核准才能離開的畫面。
  *（BUG-03：離線機器被推導到待審畫面，而待審永遠不會通過 —— 口令開考的入口因此不可達。）*
- **FR-041**: 登入成功後，若全域階段已經是「考試中」，機器 MUST 在該次登入流程內取得解讀能力並還原考卷，不得等待下一次階段變更。取得考卷或解讀能力失敗 MUST 明確回報，不得以空白的考試畫面呈現。
  *（BUG-05：解讀能力只在階段「變更」時取得；重新入場時階段早已是考試中，於是永遠不會觸發。）*
- **FR-042**: 學生機器 MUST NOT 依賴僅在渲染程序存在的非標準 API 取得本機檔案路徑。上傳與評測所需的檔案路徑 MUST 由主程序側提供的介面取得。
  *（BUG-07：`File.path` 已於 Electron 32 移除，評測因此收到 `undefined`。）*
- **FR-043**: 全域 reset MUST 一併清空機器上尚未送出的補送佇列（作答、分數、行為紀錄），使下一場考試不會收到上一場的殘留資料。

### Non-Functional Requirements (Constitution Mandated)

- **NFR-SEC**: 考卷的機密部分在開考前不得以可讀形式存在於學生機器；入場閘門不得可被繞過；被拒絕的請求不得產生副作用。
- **NFR-CONC**: 開考時刻的解讀能力取得 MUST 能承受全場機器同時請求，且該時刻的資料傳輸量 MUST 顯著小於考卷本身。
- **NFR-TYPE**: 考卷公開部分、機密部分與解讀能力的資料形狀 MUST 在後端與學生端兩側皆有嚴格的型別驗證，且兩側的定義 MUST 有機制防止靜默脫鉤。

### Key Entities

- **考試階段**：全域唯一的考試進度標記，五個互不重疊的值，單向推進，可經 reset 回到起點。
- **考試裝置**：一台考試機器的身分，包含其註冊狀態、綁定的學生、連線狀態與最近一次環境檢查結果。裝置身分可被清除並重建（重來）。
- **考卷公開部分**：開考前允許離開後端的資訊集合 —— 考試識別、應試名單、評測上限、每題所需語言與資源上限，以及以監考口令保護的解讀能力載體。
- **考卷機密部分**：題目敘述、配分結構、所有測資與解法限制。以獨立於裝置身分的方式保護。
- **解讀能力**：使機密部分可讀所需的資訊。由後端持有並扣留至開考，有線上與離線兩條取得路徑。
- **入場申請**：註冊關閉後的入場請求，含其類型、來源裝置與位置、原綁定學生，以及助教判斷所需的佐證。
- **作答與成績**：以學生為索引，獨立於裝置身分，不因重來而清除。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在開考之前，考試機器上不存在任何可讀的題目敘述或測資 —— 在已完成登入的機器上檢視，0 筆測資可讀。
- **SC-002**: 考試機器在考試中重新啟動後，經一次助教核准即可回到考試，且已提交的作答 100% 復原。目前此路徑的成功率為 0%。
- **SC-003**: 後端完全不可用時，仍有 100% 的機器能開考並完整完成考試。
- **SC-004**: 開考時刻每台機器需向後端取得的資料量，小於考卷本身的 1%。
- **SC-005**: 全域 reset 後，同一批機器無需任何人工介入即可重新完成註冊，成功率 100%。
- **SC-006**: 每個階段的操作矩陣可被逐項驗證：任一階段中不被允許的操作，被拒絕的比率為 100%。
- **SC-007**: 助教處理一筆入場申請時，無需查詢其他畫面即可判斷其類型與適當處置。
- **SC-008**: 網路中斷後恢復，中斷期間產生的作答與評測結果 100% 補送成功，且不需學生重複操作。
- **SC-009**: 還原後的考卷與現行結構等價 —— 評測、畫面與規則檢查的既有行為 0 處需要修改。
- **SC-010**: 全域 reset 後，所有學生機器在 5 秒內離開原畫面回到等待畫面 —— 停留在舊畫面的機器數為 0。
- **SC-011**: 已佈署 `pre_settings.json` 的機器，啟動到進入等待畫面的過程中，要求輸入連線設定的次數為 0。
- **SC-012**: 一次綁定衝突（重複登入／換機）產生的助教待審申請筆數 ≤ 1；目前為每 5 秒 1 筆且無上限。
- **SC-013**: 重新入場並經助教核准後，考試中的機器取得完整考卷的成功率 100%；目前為 0%（畫面空白且無錯誤訊息）。
- **SC-014**: 桌面版的評測與執行程式碼功能成功率 100%；目前為 0%（`paths[0]` 型別錯誤）。

## Assumptions

- **考試機器為一次性使用**：一場考試佈署一次，考後不再沿用。因此不需要向後相容或資料遷移，破壞性變更可直接進行，但後端與學生端的佈署必須是原子的。
- **監考人員在場**：開考口令由監考現場宣讀，入場例外由助教即時處理。整套設計以「現場有人」為前提，這是校內考試相對於遠端考試的優勢。
- **金鑰不落地**：學生機器上的身分金鑰僅存於記憶體，永不寫入磁碟。這是既有的刻意設計，其後果（重啟必須重新入場）由重來路徑承接。
- **口令採簡短形式**：依決策採用簡短的監考口令，其強度即為考卷在開考前的保護強度。攻擊窗口限於學生就座至開考之間，且需在監考視線內進行。此風險已被接受。
- **未提交的本機作答可遺失**：系統只保證已提交內容的復原。後端具備作答的自動下載與恢復功能，並有一定程度的備份。
- **既有的環境檢查機制沿用**：以合成探針驗證工具鏈、逾時與記憶體限制，不引入以真實題目為基礎的驗證題。
- **考試時長不由系統掌管**：不做本機倒數；考試結束由管理員觸發，後端不可用時退化為人工程序。
- **助教佇列的規模問題不在本次範圍**：全班同時重啟造成的待審壅塞，另案處理。

## Out of Scope

以下項目在設計討論中被提出，但明確排除於本功能之外：

- 以真實題目為基礎的驗證題（canary），以及考試時長與本機倒數
- 助教待審佇列的自動放行規則、批次核准與事件聚合
- 學生身分憑證由學生端自行簽發的既有缺陷（獨立於本功能，建議優先處理）
- 分數由學生端自報的既有行為（建議以「以複判為準 + 差異報表」的流程處理）
- 管理端憑證預設值、壓測模式的生產環境防護、時鐘偏移容忍度、反向代理下的來源識別
